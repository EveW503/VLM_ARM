替换 MoveIt 的三种方案

目标：去掉 MoveIt，用轻量 IK + 简单插值替代。当前简化版无碰撞场景。

A

PyKDL — 零新依赖，直接用 KDL Python 绑定

优点

  • 你和 ROS 2 已经装了 KDL (MoveIt 的 KDL 插件依赖它)
  • pykdl_utils / urdf_parser_py 可读取 URDF 构建运动学链
  • 行为与当前 KDL 插件一致，已有参数 (search_resolution, timeout) 可复用
  • 纯 Python，调试友好

缺点

  • KDL 对 5-DOF 臂的数值 IK 收敛率不是最优
  • PyKDL 文档较少
B

trac_ik — 收敛更好的 IK 求解器

优点

  • 收敛率显著优于 KDL (尤其是关节极限附近)
  • ROS 2 有包: trac_ik_lib + trac_ik_python (pip install trac-ik-py)
  • 同时运行两个求解器 (KDL + SQP)，取先成功的
  • 配置简单: 只需 URDF + base_link + tip_link

缺点

  • 新增依赖，需要手动安装
  • 求解速度略慢于单 KDL (但 5-DOF 影响可忽略)
C

保留 MoveIt 骨架，只砍 Planning 管线

优点

  • 最小改动：继续用 MoveGroup action 发 IK 请求
  • Planning Scene 清空/不发布，碰撞自然不介入
  • compatible with 现有 _send_move_request 封装
  • 改动量最小 (~100 行)

缺点

  • MoveIt 的重量级依赖仍在
  • MoveGroup 内部仍走 OMPL 规划流程 (即使无障碍也要跑)
  • planning_time=5s 的开销去不掉
  • ACM bug 等历史问题无法根治
  • 本质是绕过问题而非解决问题

推荐方案

推荐方案 A (PyKDL)，理由：

  • 你已经对 KDL 的行为和参数有深入理解 (position_only_ik, search_resolution=0.005)
  • 不引入新依赖，PyKDL 随 ROS 2 已安装
  • 5-DOF 臂的工作空间简单，KDL 的收敛率完全够用
  • 如果后续发现 KDL 不够稳，可以无缝升级到 trac_ik (方案 B)，因为调用接口类似

不推荐方案 C：砍 MoveIt 就是为了轻量，留着 MoveGroup 骨架失去意义。
