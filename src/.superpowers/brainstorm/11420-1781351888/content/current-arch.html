当前架构: MoveIt 在抓取流程中的角色

SO101 5-DOF 臂，KDL kinematics_solver，position_only_ik=True

MoveIt 现在做了什么

实际用到的功能

  • IK 求解 (KDL plugin, 5-DOF 只解位置)
  • 运动规划 (OMPL → 碰撞避让)
  • Cartesian path (compute_cartesian_path)
  • Planning Scene (碰撞物体注册/附着)
  • 轨迹执行编排

痛点

  • ACM bug: ApplyPlanningScene 覆盖 SRDF，gripper↔jaw 误报
  • position_only_ik=True 下 KDL 解不了姿态 → 建大量 workaround
  • 5s planning_time 太慢
  • 配置复杂，调试困难
  • MoveIt 本身约 100MB+ 依赖

当前抓取流程中的 MoveIt 调用点

  IDLE → SETUP        ← PlanningScene: add collision object
       → PRE_GRASP    ← MoveGroup action (/move_action): IK + 规划 + 执行
       → [PUSH_SWEEP] ← compute_cartesian_path: 3 航点
       → APPROACH     ← compute_cartesian_path: 1 航点 (直线下探)
       → GRASP        ← AttachLink + PlanningScene attach
       → LIFT_PLAN    ← MoveGroup action
       → TRANSPORT    ← MoveGroup action
       → PLACE        ← DetachLink + PlanningScene detach
       → IDLE

共 3 个 MoveGroup 规划 + 2 个 Cartesian path (推扫 + 下探)

核心矛盾

这是一个 5-DOF 臂，工作空间几乎无障碍物，任务是最简单的 pick-and-place。

MoveIt 设计目标是一般性操作场景（多障碍物、多自由度、复杂约束），用在这里是牛刀杀鸡。

你的直觉是对的 —— 移掉 MoveIt 值得认真评估。
