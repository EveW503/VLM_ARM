### 1.4 调试发现的关键踩坑

| 问题 | 根因 | 修复 |
|------|------|------|
| `/camera/color/image_raw` 无发布者 | Gazebo 相机插件用 sensor name 前缀，实际 topic 为 `/camera/gemini_335/image_raw` | 改 vlm_bridge 订阅路径 |
| VLM 返回像素坐标越界 | Qwen3-VL 使用归一化坐标 [0,1000]，非原始像素 | 加 `px/1000*w` 转换 |
| 深度图 reshape 失败 | Gemini 335 输出 32FC1 (float,m)，非 16UC1 | camera_utils 自动识别 encoding |
| TF 变换报 PointStamped 不支持 | 函数内动态 import，TF2 类型注册缺失 | 加 `import tf2_geometry_msgs` |
| 起始状态碰撞导致规划失败 | ee_camera_link 碰撞体与 gripper 重叠 | SRDF 加碰撞禁用对 |
| 物体被撞飞 | MoveIt 不知道物体存在，路径直穿 | PSM add_object + allow_collision + attach |
| 抓取后 MoveIt 不知道物体附着 | 只有 Gazebo AttachLink | 双层同步: MoveIt attach_object |
| 深度 Z 定位不准 (地面 vs 物体顶部) | 单点像素深度查询点到背景 | bbox 区域 min depth + 中心 XY |
| APPROACH 阶段自碰撞 | fix_start_state_collision 不用 ACM, jiggle 不够 | 待解决 (试过 jiggle_fraction=0.1, 用户回滚了) |

### 1.5 PSM 状态 (2026-05-13)

当前 PSM 架构存活但 ApplyPlanningScene 始终超时。已确认 service 可手动调用并返回 success=True，rclpy Client 调用链路是瓶颈。time.sleep 循环 + MultiThreadedExecutor 可维持回调链路不断，但 service 响应仍无法被 client future 捕获。

**当前策略**: PSM 超时仅 warning，fallback 到旧行为继续抓取。

## 3. 关键架构决策

### 3.1 VLM API 选择

| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| GPT-4o | 多模态能力强，JSON 格式输出稳定 | 需付费 API Key | **推荐** |
| Claude Sonnet 4.6 | 推理能力强，编程生态好 | 需 API Key | 备选 |
| 本地模型（如 Qwen2.5-VL） | 免费、无网络依赖 | 需要 GPU，部署复杂 | 时间不够不建议 |

**建议**：先用 GPT-4o，API Key 从环境变量读取，后续可替换。

### 3.2 相机选择

| 场景 | 相机选择 |
|------|----------|
| VLM 图像输入 | 手眼相机（ee_camera）—— 接近抓取视角 |
| 2D→3D 深度来源 | 手眼相机 —— 深度图与 RGB 对齐 |
| 外部先验 | 外部 Gemini 335 —— 可选，用于更大视野的场景感知 |

### 3.3 抓取流程状态机

```
IDLE → (收到目标位姿) → PRE_GRASP → (Cartesian: 下移) → GRASP → 
    (AttachLink) → POST_GRASP → (Cartesian: 抬起) → TRANSPORT → (Cartesian: 就位) → 
    PLACE → (DetachLink) → IDLE
```

### 3.4 排障策略映射

| VLM 标签 | 碰撞处理 | 轨迹类型 |
|----------|----------|----------|
| `rigid` | 保留碰撞体，MoveIt 自动绕行 | 默认规划 |
| `deformable` | 临时移除碰撞体 | 先推扫（水平 sweep），再抓取 |

## 4. 风险清单

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| VLM API 延迟过高（>5s） | 中 | 系统中实时性差 | 在 prompt 中限制最大响应 token，预提示 VLM 快速决策 |
| MoveIt 在遮挡场景规划频繁失败 | 高 | 指标不达标 | 调大 planning_time，尝试 RRTConnect / 其他 planner |
| 手眼相机深度图与 RGB 对齐有误差 | 低 | 2D→3D 定位不准 | 用 camera_info 验证内参，Gazebo 仿真中通常精确 |
| WSL2 性能不足（Gazebo + MoveIt + RViz） | 中 | 运行卡顿 | 关闭 RViz 渲染，减小仿真更新频率 |
| 草莓植株模型碰撞体过于复杂 | 中 | 规划超时 | 简化碰撞体或降低 collision 精度 |
| LinkAttacher 附着物体后姿态不稳定 | 低 | 物体滑落 | 在 attach 后增加短暂 wait，调整物体质量 |
